## RCA

### P-01：積んだ PR が閉じた

- なぜ 1：上の PR の base が、マージ時に消えたブランチだった。
- なぜ 2：GitHub は、base のブランチが消えると PR を付け替えずに閉じる。それを知らずに、下から順に `--delete-branch` を付けてマージした。
- なぜ 3：積んだ PR をまとめてマージする手順を決めていなかった。
- 根本原因：積んだ PR のマージの順番と base の付け替えを決めた手順がなかった。
- 再発防止策：上の PR すべての base を先に main へ替えてから下から順にマージする、とメモリに書いた（済み）。

### P-02：独立したプロジェクトを持ち込んだ

- なぜ 1：同じマシンに Lean の設定がある別のリポジトリを見つけ、そのまま使えると考えた。
- なぜ 2：兄弟のリポジトリが互いに独立かどうかを、確かめる手順がなかった。CLAUDE.md には別名義の区別しか書いていない。
- 根本原因：近くのリポジトリを、確かめないまま雛形や根拠に使ってよいとみなしていた。
- 再発防止策：そのプロジェクトを雛形・設定元・参照先・根拠の数字に使わない、とメモリに書いた（済み）。

### P-03：zsh で変数が分かれない（再発）

- なぜ 1：`for p in $P` と `uv run scripts/$s` が、zsh では空白で分かれない。
- なぜ 2：前回の T-07 は the-method スキルの落とし穴にだけ書き、ほかの作業では読まれない場所だった。
- 根本原因：再発防止策を、その場面でしか読まれない場所に置いた。
- 再発防止策：いつも読まれるメモリに、書き方（直接並べる、`${=P}`、`bash -c`、1 行ずつ `&&`）と、ループのあとで生成物の数を確かめることを書いた（済み）。
