# 行政区別の選択関数の比較（Issue #81）

今回の区分一定の案では、選択関数の偏りの低減を確認できなかった。
都道府県別で `|mean(true−proc)|` が小さくなったのは 16 ビン中 3 ビンで、平均偏りの RMS は
R=50 の 0.078671 に対し 0.084362。これらの数は Rust の集計による。
実測の ζ は多くのビンで 0 に近づくが、ξ も大きく変わるため、既存基準の代替として採用する根拠は得られていない。

2026-11-14。コスモス 2026-11-12 の選別済みカタログ、日本の e-Stat 人口格子、行政メッシュ対応一覧を使用。
計算と表の集計は Rust。ノートの TeX は変更していない。

選択関数は区分の店舗数 / 区分の人口。七地方（中国・四国は合同、沖縄は九州）と都道府県別の二種類を実装した。
境界メッシュは最小の県番号に一意に割り当てた。行政一覧にない人口格子は `50324388` と `50324389` の二つで、
外部の最寄り既知メッシュ `50325331` に割り当てた（中心間距離 9.322 km と 10.341 km、上限 25 km）。
店舗の細かい位置から地方境界や人口を推定していない。ただし区分ごとの店舗数は同じ標本から推定するため、完全な外生的選択関数ではない。

模擬データは従来の `clustered_mocks` と同じ Neyman–Scott 模型（m=14、σ=15 km）、同じ生成基準 R=50、同じ seed=1。
ランダム 8,000 点、参照 50,000 点、点の池 160,000 点、辺の範囲 2–32 km を対数で 4 等分。
追加した行政区別の proc の抽出は別の乱数列を使い、従来の模擬店舗と true / SmoothRatio proc の乱数列は保つ。
比較の `true−proc` は、選択関数を再推定する効果と、生成基準 R=50 を行政区一定で近似する模型の不一致を両方含む。
局所的な固まりを吸収しなくなる効果だけを分離した測定ではない。

地方別の実測 ξ は 3 / 6 / 12 / 24 km で 0.363212 / 0.326985 / 0.288472 / 0.196917。
R=50 の 0.194078 / 0.166658 / 0.145789 / 0.085019 から大きく変わったため、都道府県別も測った。
都道府県別も ξ が変わることを確認しており、既存の二点結果のそのままの代替とは扱えない。

再現コマンド（共有 data の既存出力を守るため、再実行では未使用のタグを選ぶ）：

```sh
cargo build --release --bin zeta --bin zeta_clustered --bin zeta_clustered_summary --bin zeta_selection_summary
C=data/cosmos_site/cosmos_site_clean_2026-11-12.csv
target/release/zeta 2026-11-12 --country jp --stores "$C" --chain COSMOS --footprint 50 --xi on --n-random 8000 --n-ref 50000 --seed 1 --tag ext_smooth
target/release/zeta 2026-11-12 --country jp --stores "$C" --chain COSMOS --regional on --xi on --n-random 8000 --n-ref 50000 --seed 1 --tag ext_regional
target/release/zeta 2026-11-12 --country jp --stores "$C" --chain COSMOS --regional prefecture --xi on --n-random 8000 --n-ref 50000 --seed 1 --tag ext_prefecture
# まず runs=1 で時間測定。点の池を含む初期化は各呼び出しで一度だけ行われる。
target/release/zeta_clustered 2026-11-12 --country jp --stores "$C" --chain COSMOS --footprint 50 --regional on --children 14 --sigma 15 --runs 1 --n-random 8000 --n-ref 50000 --seed 1 --tag ext_bench
```

検証：`cargo test`、`cargo clippy --all-targets -- -D warnings`、`scripts/check_layers.sh crates/retail-cosmology/src`。
`ext_smooth.csv` は既存の `zeta_jp_2026-11-12_cosmos_fp50_t8000.csv` と `cmp` でバイト一致。
共有の既存出力を上書きする `scripts/check_outputs.sh` は実行せず、今回触れる経路を専用タグで照合した。
既定の選択関数・演算・既存出力形式は変更していない。

時間測定は全体 451.92 秒、点の池の生成まで 377.1 秒、初回計測の追加が約 73.5 秒だった。
20 回は初期化を共有するため約 31 分と見積もり、都道府県別で 20 回を選んだ。回数の削減はしていない。

```sh

```

七地方の runs=1 は時間測定と候補の確認用であり、平均の誤差を推定できない。
以下の統計的比較で「regional」と書かれた列は **都道府県別** の値である。

20 回の本計算は Rust の `Instant` では 1,488.8 秒（約 24.8 分）で完了した。
一方、外部の `/usr/bin/time` は `real 18197.33` 秒、`user 1383.62` 秒、`sys 8.64` 秒を記録した。
壁時計では 1 時間を超えている。ホスト休止などで時計の計測対象が違った可能性はあるが、原因は未検証。
runs=1 の計測に基づく開始時の見積もりは 1 時間以内であり、計算途中では内蔵タイマーだけが進捗として出ていた。
この時間の不一致は、計算時間の短縮と混同せず両方を報告する。

20 回の従来列（ζ の最初の 10 列、ξ の最初の 5 列）は、既存の同条件の 20 回ファイルと `cmp` でバイト一致した。
既存の出力値が変わる変更はない。

## 残る点

- 行政区内の出店傾向を一定としたため、生成基準 R=50 との模型の不一致が残る。今回の true−proc だけでは、局所的な固まりの吸収と模型の不一致を分離できない。
- 都道府県の境界をならす案、独立した外部の出店データ、地域内の出店傾向を表す外部変数は未評価。
- 店舗数は同じ標本から推定する。局所配置への依存は除いても、行政区ごとの合計数の揺らぎを吸収する。
- m=14、σ=15 km は従来の R=50 の proc の ξ に合わせた設定。新しい基準で模型のパラメータを合わせ直してはいない。
- 表の ζ の誤差は 20 個の mock 間での paired difference の平均の誤差。実測値の誤差、固定した参照点・ランダムカタログの不確かさ、ビン間の共分散を表していない。
- 行政区の境界メッシュの規約と二つの補完メッシュに依存する。壁時計と内蔵タイマーの差の原因も未検証。
