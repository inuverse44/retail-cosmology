# ADR 009: 親ごとの子の抽出で一点密度を調べる基準を作る

## Context

`clustered_mocks` は親を点の池から一様に選び、3σ 以内の候補からガウス重みで m 個の子を重複なしで選ぶ。
近傍に m 個の点がない親は使わない。親ごとに重みを正規化するため、子の平均密度が池の密度に一致する保証はない。
main の先の研究のノート第 5 節には密度のずれと相関が混ざる式 (5) が加わった（2026-11-14 確認）。
従来の true という列名は生成時の親の基準であり、子の一点密度に一致するとは限らない。

## Decision

1. 既存のランダムカタログ Engine に、親を池から選んで子を一つだけ選ぶ抽出を足す。親の採用条件（近傍に m 個以上）、3σ の打切り、ガウス重みは従来と同じにする。各出力点に独立な親を選ぶので同じ親を共有することによるクラスタ相関は入れない。
2. `zeta_clustered --match on` を明示した場合だけ match の ζ・ξ・match の RRR で換算した expected_match を既存列の末尾に足す。match 用の乱数は従来の rng_m と独立にし、各回で新しいカタログを撒く。専用タグを必須とする。
3. Manager が既存と同じ点の池を生成し、Engine に抽出を依頼する。既存の店舗生成コードと true / proc / expected の計算は変えない。
4. Manager が人口格子の約 10 km 格子ごとに池と match の個数を集める。密度比の分布と分散の計算は既存の推定量 Engine に足す。池の個数を true の大きな標本として使う。match は独立な二群にも分け、(g_A−1)(g_B−1) の重み付き平均から標本雑音の自己積を含まない密度のずれの目安を求める。
5. ResourceAccess の既存の CSV 読み書きで新規タグの結果だけを保存する。Client は Manager を一つ呼び、表は Rust で集計する。

### 本 ADR で決定しないこと

- m 個を重み付き重複なしで選んだ全子の周辺分布と、「最初の一個」の分布の厳密な差。この実験は指示された後者を測り、残差があれば前者を次の候補として扱う。
- 固定した親の数、有限の池、同じ親の三角形による見込みの有限標本補正は変えない。
- ノートの文章や既存の true / proc という列名は変えない。

## Consequences

- 平均密度のずれを調べる基準と、店舗からの再推定の基準を同じ模擬店舗に当てられる。
- match が見込みに合うかは実測で判断する。合うことをコードの前提にしない。
- 約 10 km 格子の比には有限標本の雑音がある。個数の下限、重み、二群の相互積を明記する。
- 既定の出力形式と乱数列を保ち、追加オプションでも従来列が既存ファイルと一致することを照合できる。

## Alternatives Considered

- 基準人口だけを細かく直す：子の条件付き正規化という問題に答えない。
- 子の集団を多数生成してから選ぶ：同じ親を共有する相関が混ざり、独立な基準にならない。
- 従来の店舗生成を直す：既存結果との照合ができなくなるため、この診断では行わない。
