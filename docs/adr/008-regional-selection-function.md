# ADR 008: 地方の店舗数と人口から区分一定の選択関数を作る

## Context

`SmoothRatio` は店舗座標から密度をならすため、短距離の固まりの一部も基準に吸収する。
`manager::three_point::clustered_mocks` は同じ模擬データに true と proc の基準を当て、この差を測っている。
既存の `engine::selection::region(Chain::Trial, ...)` は都道府県を七つの地方（中国・四国は合同、沖縄は九州）に分ける。
`access::population::read_mesh_prefectures` は行政区と三次メッシュの対応を既に読む。
以上を 2026-11-14 の本ブランチで確認した。

## Decision

1. 既存の選択関数 Engine に `RegionalRatio` を足す。入力はメッシュと地方の対応、地方ごとの人口、店舗座標であり、値は地方の店舗数 / 地方の人口とする。`prefecture` を選ぶと都道府県ごとの比に細分化する。地方内の細かい店舗配置を使わない。店舗数は同じ標本から推定するので完全に外生ではない。
2. ResourceAccess の人口モジュールに全都道府県のメッシュ対応の読み込みを足す。複数県に載る境界メッシュは番号が最小の県に一意に割り当て、人口を二重計上しない。地方の定義は既存の選択 Engine で Manager が決め、選択関数 Engine へデータとして渡す。対応一覧にない人口・店舗メッシュは、外部の既知メッシュの最寄り中心（25 km 以内、同距離はメッシュ番号順）へ割り当て、補完数を表示する。25 km 以内に対応がなければエラーにする。これは人口格子と行政対応の収録範囲の違いに対処する規約（対応のない格子が二つあった）で、店舗密度は使わない。
3. 人口の実数和で分母を計算する。参照点の有限標本から人口を推定しない。ランダムカタログ Engine に格子ごとの追加重みで直接抽出する機能を足し、地方別の抽出には棄却法の上限推定を使わない。
4. Manager が読み込み、地方の対応、選択関数の推定、抽出、二点・三点計算を組み合わせる。Engine 間や ResourceAccess 間の呼び出しは増やさない。
5. `zeta --regional on|prefecture` で地方別または都道府県別の基準を選び、`--xi on` で同じランダムカタログによる二点の表も保存する。`zeta_clustered --regional on|prefecture` は既存の模擬データ生成と SmoothRatio の乱数列を保ち、独立した乱数列で地方別 proc を追加計測する。true は従来の R=50 の生成基準のままとし、共通の模擬データ上の基準の違いを比較する。
6. 層チェックに既存の違反が二つあるため、診断の参照点数は診断 Manager 内の定数にし、分散 Client の Weight は分散 Manager を通して公開する。値や演算は変えない。
7. 既存の既定値と出力形式は保つ。新規実験は専用タグで保存する。

### 本 ADR で決定しないこと

- 地方内の滑らかな出店傾向をどう表すか、さらに細分化するか：今回の偏りと実測の比較を踏まえた後続の実験に委ねる。
- 真の選択関数の特定、模擬データの模型の妥当性：解析の判断であり、この ADR では保証しない。

## Consequences

- 地方内で店舗を動かしても選択関数は変わらず、局所的な固まりの吸収を減らせる。
- 地方の合計店舗数の揺らぎは引き続き吸収する。
- 地方の境界に段差があり、地方内の出店傾向を捨てる。R=50 の真の基準との差にはこの模型の不一致も含まれる。true−proc が小さくなる保証はない。
- 境界の位置の精度は三次メッシュであり、境界メッシュの割り当てに規約が必要になる。
- 地方内の傾向を残すため、実際の ξ や ζ が大きく変わる可能性がある。

## Alternatives Considered

- 店舗密度の平滑化幅だけを広げる：短距離の配置への依存を残す。
- 都道府県ごとに比を推定する：細かい出店傾向を表せるが推定する自由度と固まりの吸収も増す。地方で実際の ξ が大きく変わったため、県別も選択可能にして比較する。
- 参照点で地方の人口比を推定する：既存の人口格子から正確な和を取れるので不要。
