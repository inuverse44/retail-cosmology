# ADR 007: 三つ組の数え上げは新しい Engine として足し、二点の数え上げには手を入れない

## Context

二点相関関数の先の研究として、店舗の三点相関関数 $\zeta$ を測る（ノート `notes/retail-cosmology-beyond.tex`、置き場所は ADR-006 の Decision 項 4（先の研究のノート））。
推定量は Szapudi と Szalay の $(DDD - 3DDR + 3DRR - RRR)/RRR$ を使う予定で、店とランダムカタログから三つ組（三角形）の数を数える必要がある。

今のコードで関係する所は次のとおりである（2026-11-14 に main で確認）。

- 二点の数え上げは Engine の `engine::pair_count` にある。同じカタログの中の組と二つのカタログの間の組を、すべての組について距離を測って数える（総当たり）。jackknife のために、領域の組ごとにも数える。
- 推定量と誤差は Engine の `engine::estimator` にある。二点の推定量、jackknife、ビンをまとめた値（ADR-002）、模擬データとの比較がここに入っている。
- 単位球面上の近くの点を探す格子は Utility の `util::spatial::UnitGrid` にある。今は選択関数（`engine::selection_function`）だけが使っている。
- 層の間で受け渡すデータの形は `contract` にあり、二点の数は `PairCounts`、`CrossPairCounts` である。

二点の数え上げの出力は、発表したノート `notes/retail-cosmology.tex` の数字の元である。
ADR-001 は、同じ入力と同じ乱数の種から 1 バイトも違わない結果が出ることを前提にしている。

三つ組を総当たりで数えると、点の数 $N$ に対して $N^3/6$ 通りある。
ランダムカタログ（今は $20{,}000$ 点）では約 $1.3 \times 10^{12}$ 通りになり、総当たりでは数えられない。
距離の上限より遠い三つ組は数えず、近くの点だけを格子で探す必要がある。

三角形の取り方（三辺で表すか、二辺と間の角で表すか）とビンの切り方は、ノイズの大きさを見ながら変える見込みである。
二点の数え上げは発表したノートのために固まっており、変わりやすさが違う。

## Decision

1. 三つ組の数え上げは、新しい Engine として足す。二点の数え上げ（`engine::pair_count`）は変えない。
   既存の実行ファイルの出力は、この変更の前と後で 1 バイトも変わらないことを `scripts/check_outputs.sh` で確かめる（ADR-001 の前提）。
2. 三つ組の数え上げでは、近くの点を Utility の空間格子（`util::spatial`）で探し、距離の上限より遠い三つ組は数えない。総当たりはしない。
3. 三点の推定量は、二点と同じ推定量と誤差の Engine（`engine::estimator`）に足す。jackknife、ビンをまとめた値、模擬データとの比較は二点と同じものを使う。
4. 三つ組の数は、`contract` に新しい型を足して層の間で受け渡す。
5. 「店舗の三点相関関数を測る」を使用例として、Manager を一つ足す。データの読み込み（店、人口の格子、選択関数）は二点と同じ ResourceAccess を使う。

### 本 ADR で決定しないこと

- 三角形の取り方、ビンの切り方、距離の上限の値：ノート `notes/retail-cosmology-beyond.tex` に委ねる。
- ランダムカタログどうしの三つ組（RRR）を数える工夫（点の数を減らす、数え方を変えるなど）と、jackknife で三つ組をどの領域に割り当てるか：コード（三つ組の数え上げの Engine の文書コメント）に委ねる。
- モジュール、型、関数、実行ファイルの名前：コードに委ねる。
- toy model（相関のない点、中心のまわりに衛星を撒いた点）の作り方：コード（toy model の Manager の文書コメント）に委ねる。

## Consequences

- 発表したノートの数字を出すコードに触れずに、三点相関を試せる。
- 二点と三点で、数え上げのコードに似た部分ができる（距離のビン、領域ごとの数え上げ）。共通にしないのは、二点の側を変えないためで、重複は受け入れる。
- 空間格子が数え上げにも使われるようになり、Utility の `util::spatial` の正しさが三点の結果に効く。三つ組の数は、小さい点の数で総当たりの数と一致することをテストで確かめる。
- 推定量の Engine に三点の推定量が入るので、このモジュールは二点と三点の両方の規則を持つ。

## Alternatives Considered

- **二点の数え上げを一般化して、$n$ 点を数える Engine にする**：コードは一つにまとまるが、発表したノートの数字を出すコードを書き換えることになる。変わりやすさの違う二つを一緒にするので選ばなかった。
- **三点相関を Python の既存のライブラリで測る**：数え上げは速いかもしれないが、選択関数つきのランダムカタログ、jackknife の領域、模擬データを二点と同じ手順で作れなくなる。このリポジトリでは計算を Rust に置いているので選ばなかった。
- **三つ組も総当たりで数える**：ランダムカタログで $10^{12}$ 通りになり、時間が足りないので選ばなかった。

## 関連する ADR

- ADR-001（変わりやすさで層に分ける）：新しい Engine と Manager はこの層の分け方に従う。
- ADR-002（ビンをまとめた値は、単純な平均に jackknife の誤差をつける）：三点でも同じまとめ方を使う。
- ADR-006（notes/ の置き方）：三点相関の結果は、先の研究のノートに書く。
